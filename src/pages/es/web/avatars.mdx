## Obtener el Avatar del Usuario

Los avatares son una forma increíble para que los usuarios se expresen. Para obtener el avatar del usuario, solo necesitas su **nombre**. Si solo tienes su dirección, ve [nombres primarios](/es/web/reverse#get).
Los siguientes fragmentos de código te permiten obtener el avatar de un usuario.

:::code-group

```tsx [Wagmi]
// https://wagmi.sh/react/hooks/useEnsAvatar
import { useEnsAvatar } from 'wagmi'

function App() {
  const { data: ensAvatar } = useEnsAvatar({
    address: 'nick.eth',
    chainId: 1, // (1 = Ethereum Mainnet, 11155111 = Sepolia)
  })

  return (
    <img
      src={ensAvatar || 'https://avatars.jakerunzer.com/nick.eth'}
      alt="nick.eth"
    />
  )
}
```

```ts [Ethers]
// https://docs.ethers.org/v5/api/providers/provider/#Provider-getAvatar
const ensAvatar = await provider.getAvatar('nick.eth')
```

```ts [Viem]
// https://viem.sh/docs/ens/actions/getEnsAvatar.html
import { normalize } from 'viem/ens'

import { publicClient } from './client'

const ensAvatar = await publicClient.getEnsAvatar({
  name: normalize('nick.eth'),
})
```

```py [Web3.py]
# https://web3py.readthedocs.io/en/latest/ens_overview.html#read-text-metadata-for-an-ens-record
from ens.auto import ns

avatar = ns.get_text('alice.eth', 'avatar')
```

```go [Go]
package main

import (
	"fmt"

	"github.com/ethereum/go-ethereum/ethclient"
	ens "github.com/wealdtech/go-ens/v3"
)

func main() {
	client, _ := ethclient.Dial("https://rpc.ankr.com/eth")

	domain, _ := ens.Normalize("nick.eth")
	resolver, _ := ens.NewResolver(client, domain)
	avatar, _ := resolver.Text("avatar")

	fmt.Println("Avatar: ", avatar)
}
```

:::

### El Servicio de Metadatos

El [servicio de metadatos](https://metadata.ens.domains/docs) es ejecutado por ENS Labs. Es un servicio web gratuito que te permite recuperar el
avatar de un nombre ENS a través de una solicitud web, en lugar de agregar lógica extra a tu aplicación e interactuar
con un nodo ethereum. Esto es por supuesto centralizado y debe usarse si es absolutamente necesario.

## ¿Qué es exactamente un Registro de Avatar?

Un registro de avatar es simplemente un [registro de texto](/es/web/records) que tiene "avatar" como su clave y una URI como su valor,
con algunas reglas sobre qué esquemas URI son soportados y cómo procesarlos. Para más información, ve [ENSIP-11](/ensip/12).

## Esquemas URI soportados

Se espera que los clientes soporten varios esquemas URI, que no siempre son URIs web, por lo que el resultado final que ves en tu aplicación
variará dependiendo de cómo la librería que estás usando ha decidido manejar los registros de avatar.

- `http(s):` - Esquema URI para URLs HTTP(S). Las librerías probablemente devolverán el resultado directamente.
- `ipfs:` - Esquema URI para [hashes IPFS](). Las librerías pueden decidir obtener el resultado de una puerta de enlace pública por ti.
- `data:` - Esquema URI para [data URIs](https://developer.mozilla.org/en-US/docs/Web/HTTP/Basics_of_HTTP/Data_URLs).
  Las librerías probablemente devolverán el resultado directamente.
- `eip155:` - El esquema URI para identificadores EIP-155 para enlazar a NFTs en cadenas basadas en Ethereum. Un poco complicado
  de resolver manualmente, la mayoría de librerías deberían resolver esto por ti y devolver el recurso subyacente.

:::note
Para Avatares NFT EIP-155 el nft debe ser propiedad de la dirección de wallet a la que el nombre ENS
resuelve. Esto se hace verificando el método `ownerOf` en el contrato NFT.
:::

## Esquemas comunes que no están oficialmente soportados

- `ethereum:` - El esquema URI para direcciones de Ethereum
- `bzz:` - El esquema URI para hashes de Swarm

## Información del Archivo

Los avatares vienen en muchas formas y tamaños diferentes. No solo los esquemas URI anteriores, sino también en diferentes formatos de archivo, tamaños y más.
Aunque existen estándares para algunos de estos, los archivos **no están obligados** a seguir estos estándares.

A continuación se muestra información sobre los avatares que tu aplicación podría estar cargando.

| Propiedad del Archivo:  | Info/Recomendación                                                             |
| -------------- | ------------------------------------------------------------------------------- |
| Extensión del Archivo | Principalmente `png`, `jpeg`, `jpg`, `webp`, `gif`, `webm`, pero podría ser cualquier cosa       |
| Tamaño del Archivo      | Recomendamos tener timeouts sensibles                                           |
| Proporción de Aspecto   | Recomendamos `object-fit: cover` o establecer un color de fondo                  |
| Transparencia   | Recomendamos establecer un color de fondo ya que algunas imágenes pueden contener transparencia |

Afortunadamente la mayoría de navegadores y librerías de red tienen timeouts por defecto para comenzar, recomendamos encarecidamente que si estás haciendo cualquier descarga o obtención manual de avatar agregues un timeout sensato.
